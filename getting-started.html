Getting Started with Dashboards-as-Code

This guide walks you through creating your first Dashboards-as-Code project, from installation to a deployed dashboard.

Prerequisites

  • Node.js 18 or later
  • npm 9 or later
  • An OpenSearch Dashboards instance (local or remote) running version 2.x or later
  • Git (recommended for version control)

Step 1: Install the CLI

Install osdctl globally via npm:


npm install -g @osd/cli

Verify the installation:


osdctl --version
# osdctl version 0.1.0

Alternative installation methods:


# Via Homebrew (macOS/Linux)
brew install opensearch-project/tap/osdctl

# Via Docker
docker pull opensearchproject/osdctl:latest

Step 2: Create a New Project

Scaffold a new DaC project using osdctl init:


osdctl init --language typescript my-dashboards

This creates the following project structure:


my-dashboards/
  package.json          # Node.js project with osdctl scripts
  tsconfig.json         # TypeScript compiler configuration
  .osdctl.yaml          # CLI configuration (profiles, lint rules)
  .gitignore            # Ignores built/ and node_modules/
  src/
    dashboards/
      example.ts        # Example dashboard using SDK builders
  built/                # Build output directory

Enter the project and install dependencies:


cd my-dashboards
npm install

Step 3: Configure Connection Profiles

Open .osdctl.yaml and update the connection profiles for your environments:


defaultProfile: dev
outputDir: ./built

variables:
  team: my-team

profiles:
  dev:
    url: http://localhost:5601
    variables:
      cluster_name: dev-cluster
  staging:
    url: https://dashboards-staging.internal:5601
    variables:
      cluster_name: staging-cluster
  prod:
    url: https://dashboards.company.com:5601
    variables:
      cluster_name: prod-cluster

lint:
  require-labels: true
  require-description: true
  max-panels: 50

For authentication, set environment variables rather than storing credentials in config files:


# Basic auth
export OSD_USERNAME=admin
export OSD_PASSWORD=admin

# Or token-based auth
export OSD_TOKEN=your-api-token

See the CLI Reference for the full configuration format.

Step 4: Write Your First Dashboard

Create a new file at src/dashboards/my-first-dashboard.ts:


import { Dashboard, Panel, Query, DataSource, Variable } from '@osd/dashboards-sdk';

const dashboard = Dashboard.create('my-first-dashboard')
  .title('My First Dashboard')
  .description('A getting-started dashboard tracking web server metrics')
  .labels({ env: 'development', team: 'platform' })
  .annotation('owner', 'your-name@company.com')
  .timeRange('now-1h', 'now')
  .refreshInterval('30s')
  .addVariable(
    Variable.create('host')
      .type('query')
      .label('Host')
      .description('Select a host to filter by')
      .query("source = web_logs | stats count() by host | fields host")
  )
  .addPanel(
    Panel.create('request-rate')
      .visualization('line')
      .gridPosition({ x: 0, y: 0, w: 24, h: 12 })
      .query(
        Query.ppl("source = web_logs | where host = '$host' | stats count() as requests by span(timestamp, 1m)")
      )
      .option('showLegend', true)
      .option('legendPosition', 'bottom')
  )
  .addPanel(
    Panel.create('error-rate')
      .visualization('area')
      .gridPosition({ x: 0, y: 12, w: 12, h: 10 })
      .query(
        Query.ppl("source = web_logs | where status >= 500 | stats count() as errors by span(timestamp, 1m)")
      )
      .option('showLegend', true)
  )
  .addPanel(
    Panel.create('status-breakdown')
      .visualization('pie')
      .gridPosition({ x: 12, y: 12, w: 12, h: 10 })
      .query(
        Query.ppl("source = web_logs | stats count() as requests by status")
      )
  )
  .addPanel(
    Panel.create('top-endpoints')
      .visualization('table')
      .gridPosition({ x: 0, y: 22, w: 24, h: 10 })
      .query(
        Query.sql("SELECT endpoint, COUNT(*) as hits, AVG(latency_ms) as avg_latency FROM web_logs GROUP BY endpoint ORDER BY hits DESC LIMIT 20")
      )
  )
  .addDataSource(
    DataSource.create('web-logs-cluster')
      .type('opensearch')
      .default(true)
  );

// Output: write to YAML file
dashboard.toYAML('built/my-first-dashboard.yaml');

// Or output to JSON
// dashboard.toJSON('built/my-first-dashboard.json');

Step 5: Build

Compile the TypeScript source into a deployable YAML definition:


osdctl build -f src/dashboards/my-first-dashboard.ts -o yaml

This executes the TypeScript file and writes the output to built/my-first-dashboard.yaml.

To build all dashboards in a directory:


osdctl build -d src/dashboards/ -o yaml

To preview the output without writing files:


osdctl build -f src/dashboards/my-first-dashboard.ts --stdout

The built YAML output looks like this:


apiVersion: dashboards.opensearch.org/v1alpha1
kind: Dashboard
metadata:
  name: my-first-dashboard
  labels:
    env: development
    team: platform
  annotations:
    owner: your-name@company.com
spec:
  title: My First Dashboard
  description: A getting-started dashboard tracking web server metrics
  timeRange:
    from: now-1h
    to: now
  refreshInterval: 30s
  panels:
    - name: request-rate
      type: visualization
      visualization: line
      gridPosition:
        x: 0
        y: 0
        w: 24
        h: 12
      query:
        language: PPL
        query: "source = web_logs | where host = '$host' | stats count() as requests by span(timestamp, 1m)"
      options:
        showLegend: true
        legendPosition: bottom
    # ... additional panels
  dataSources:
    - name: web-logs-cluster
      type: opensearch
      default: true
  variables:
    - name: host
      type: query
      label: Host
      description: Select a host to filter by
      query: "source = web_logs | stats count() by host | fields host"

Step 6: Validate

Validate the built definitions against the schema:


osdctl validate

Expected output:


Validating 1 dashboard...
  my-first-dashboard.yaml    VALID

1/1 valid, 0 errors

For server-side validation that also checks data source existence and plugin availability:


osdctl validate --server --profile dev

Step 7: Preview Changes with Diff

Before deploying, see what would change compared to the currently deployed state:


osdctl diff --profile dev

Since this is a new dashboard, the output will show:


Comparing 1 dashboard against dev...

  my-first-dashboard         NEW

0 updated, 1 new, 0 unchanged

Step 8: Deploy

Deploy the dashboard to your development instance:


# First, do a dry run to see what would happen
osdctl apply --dry-run --profile dev

Output:


Applying 1 dashboard to dev (dry-run)...
  my-first-dashboard         WOULD CREATE  (v1)

1 change would be applied, 0 unchanged

When you are satisfied, apply for real:


osdctl apply --profile dev

Output:


Applying 1 dashboard to dev...
  my-first-dashboard         CREATED  (v1)

1 change applied, 0 unchanged

For production deployments, use the confirmation prompt:


osdctl apply --profile prod --confirm

Step 9: Verify in the UI

Open your OpenSearch Dashboards instance in a browser:


http://localhost:5601/app/dashboards

You should see "My First Dashboard" in the dashboard list. It will have a "Managed by code" badge indicating it was deployed via osdctl. The managed-by: osdctl label is automatically applied during deployment.

Step 10: Commit to Git

Initialize a Git repository and commit your work:


git init
git add .
git commit -m "Add initial DaC project with web server dashboard"

From here, all dashboard changes follow the standard Git workflow:

  1. Create a branch
  2. Modify dashboard code
  3. Open a pull request
  4. CI validates and diffs automatically
  5. Merge deploys to the target environment
