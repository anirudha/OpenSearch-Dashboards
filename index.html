Dashboards-as-Code for OpenSearch Dashboards

What is Dashboards-as-Code?

Dashboards-as-Code (DaC) is a workflow for defining, validating, version-controlling, and deploying OpenSearch Dashboards programmatically. Instead of manually creating dashboards through the UI, you write dashboard definitions in TypeScript (with Python, Go, and Java coming soon), store them in Git, validate them in CI, and deploy them automatically.

DaC treats dashboards the same way infrastructure-as-code tools treat cloud resources: as reviewable, testable, reproducible code artifacts.

Architecture Overview

Dashboards-as-Code is built in four layers, each building on the one below it:


+----------------------------------------------------------------------+
|  Layer 4: CI/CD Integration                                          |
|  GitHub Actions, GitLab CI, Docker, environment promotion            |
+----------------------------------------------------------------------+
        |
        v
+----------------------------------------------------------------------+
|  Layer 3: CLI (osdctl)                                               |
|  init, build, validate, diff, apply, pull, lint, preview             |
+----------------------------------------------------------------------+
        |
        v
+----------------------------------------------------------------------+
|  Layer 2: SDK (@opensearch-dashboards/sdk)                           |
|  TypeScript builders for Dashboard, Panel, Query, Variable,          |
|  DataSource. Compiles to JSON/YAML. Client-side validation.          |
+----------------------------------------------------------------------+
        |
        v
+----------------------------------------------------------------------+
|  Layer 1: Saved Objects API Extensions                               |
|  _validate, _diff, _bulk_apply, _export_clean, _schemas             |
|  Labels, annotations, optimistic concurrency, typed schemas          |
+----------------------------------------------------------------------+
        |
        v
+----------------------------------------------------------------------+
|  OpenSearch Dashboards Server / Saved Objects Store (.kibana index)   |
+----------------------------------------------------------------------+

Layer 1 (API) extends the existing Saved Objects API with validation, diff, bulk apply, labels, annotations, and typed JSON Schemas. Existing APIs and UI workflows continue to work unchanged.

Layer 2 (SDK) provides fluent TypeScript builders that compile dashboard definitions to JSON or YAML. SDKs are auto-generated from JSON Schema definitions to stay in sync with the server.

Layer 3 (CLI) is osdctl, a standalone command-line tool that orchestrates the full DaC workflow: scaffold projects, build SDK code, validate definitions, diff against deployed state, apply changes, and pull existing dashboards.

Layer 4 (CI/CD) provides GitHub Actions, GitLab CI templates, and Docker images for automated pipeline integration.

Key differentiators for OpenSearch DaC:

  • All features are fully open source with no enterprise gating.
  • First-class support for OpenSearch-native query languages (PPL, DQL, SQL, Lucene).
  • Extends the battle-tested Saved Objects API rather than building a parallel system.
  • Designed for Grafana-to-OpenSearch migration with osdctl convert.

Quick Start


# Install the CLI
npm install -g @opensearch-dashboards/cli

# Scaffold a new project
osdctl init --language typescript my-dashboards

# Enter the project and install dependencies
cd my-dashboards
npm install

# Build the example dashboard
osdctl build -d src/

# Validate
osdctl validate

# Deploy (dry-run first)
osdctl apply --dry-run --profile dev
osdctl apply --profile dev

For the full walkthrough, see the Getting Started Guide.
