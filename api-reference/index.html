API Reference: Saved Objects API Extensions

The Dashboards-as-Code feature extends the existing OpenSearch Dashboards Saved Objects API with validation, diff, bulk apply, clean export, and schema endpoints. All existing Saved Objects API endpoints continue to work unchanged.

Base URL: https://<dashboards-host>:<port>/api/saved_objects

Authentication

All API endpoints respect the existing OpenSearch Dashboards security configuration. Supported authentication methods:

Basic Auth


curl -u admin:password \
  -X POST https://localhost:5601/api/saved_objects/_validate \
  -H 'Content-Type: application/json' \
  -H 'osd-xsrf: true' \
  -d '{ ... }'

Bearer Token


curl -H "Authorization: Bearer <token>" \
  -X POST https://localhost:5601/api/saved_objects/_validate \
  -H 'Content-Type: application/json' \
  -H 'osd-xsrf: true' \
  -d '{ ... }'

SAML / OIDC

Token-based authentication obtained through your identity provider. Use the bearer token method with the token retrieved from your SAML/OIDC flow.

Note: All POST requests require the osd-xsrf: true header to prevent cross-site request forgery.

POST /api/saved_objects/_validate

Validate a resource definition against the typed JSON Schema without persisting it.

Request


POST /api/saved_objects/_validate?mode=schema
Content-Type: application/json
osd-xsrf: true

{
  "type": "dashboard",
  "attributes": {
    "title": "CPU Monitoring",
    "description": "Production CPU metrics",
    "panelsJSON": [
      {
        "panelIndex": "1",
        "gridData": { "x": 0, "y": 0, "w": 24, "h": 12, "i": "1" },
        "type": "visualization",
        "id": "cpu-line-chart"
      }
    ],
    "optionsJSON": {
      "useMargins": true,
      "hidePanelTitles": false
    },
    "timeRestore": true,
    "timeFrom": "now-1h",
    "timeTo": "now"
  }
}

Query Parameters

ParameterDefaultDescription
modeschemaValidation mode: schema (JSON Schema only, fast, offline-capable) or full (schema + server-side checks for data sources, index patterns, plugins)

Response: Success


HTTP/1.1 200 OK
Content-Type: application/json

{
  "valid": true,
  "warnings": []
}

Response: Validation Error


HTTP/1.1 200 OK
Content-Type: application/json

{
  "valid": false,
  "errors": [
    {
      "path": "attributes.panelsJSON[2].gridData.w",
      "message": "must be >= 1",
      "schemaPath": "#/$defs/panel/properties/gridData/properties/w/minimum"
    },
    {
      "path": "attributes.title",
      "message": "must be string with minLength 1",
      "schemaPath": "#/properties/title/minLength"
    }
  ]
}

Error Response Fields

FieldTypeDescription
pathstringJSON Pointer to the field that failed validation
messagestringHuman-readable error description
schemaPathstringJSON Schema path of the constraint that was violated

Examples

Schema-only validation (fast, no server state required):


curl -u admin:admin \
  -X POST "http://localhost:5601/api/saved_objects/_validate?mode=schema" \
  -H 'Content-Type: application/json' \
  -H 'osd-xsrf: true' \
  -d '{
    "type": "dashboard",
    "attributes": {
      "title": "My Dashboard",
      "panelsJSON": []
    }
  }'

Full validation (checks data sources and plugins):


curl -u admin:admin \
  -X POST "http://localhost:5601/api/saved_objects/_validate?mode=full" \
  -H 'Content-Type: application/json' \
  -H 'osd-xsrf: true' \
  -d '{
    "type": "dashboard",
    "attributes": {
      "title": "My Dashboard",
      "panelsJSON": [
        {
          "panelIndex": "1",
          "gridData": { "x": 0, "y": 0, "w": 24, "h": 12, "i": "1" },
          "type": "visualization",
          "id": "some-viz-id"
        }
      ]
    }
  }'

POST /api/saved_objects/_diff

Compare a resource definition against the currently deployed version and return a structured diff.

Request


POST /api/saved_objects/_diff
Content-Type: application/json
osd-xsrf: true

{
  "type": "dashboard",
  "id": "cpu-monitoring",
  "attributes": {
    "title": "CPU Monitoring (Updated)",
    "description": "Production CPU metrics across all clusters",
    "panelsJSON": [
      {
        "panelIndex": "1",
        "gridData": { "x": 0, "y": 0, "w": 24, "h": 12, "i": "1" },
        "type": "visualization",
        "id": "cpu-line-chart"
      },
      {
        "panelIndex": "2",
        "gridData": { "x": 0, "y": 12, "w": 24, "h": 12, "i": "2" },
        "type": "visualization",
        "id": "cpu-heatmap"
      }
    ]
  }
}

Response: Changes Detected


HTTP/1.1 200 OK
Content-Type: application/json

{
  "status": "updated",
  "diff": [
    {
      "op": "replace",
      "path": "/attributes/title",
      "oldValue": "CPU Monitoring",
      "newValue": "CPU Monitoring (Updated)"
    },
    {
      "op": "add",
      "path": "/attributes/panelsJSON/1",
      "newValue": {
        "panelIndex": "2",
        "gridData": { "x": 0, "y": 12, "w": 24, "h": 12, "i": "2" },
        "type": "visualization",
        "id": "cpu-heatmap"
      }
    }
  ]
}

Response: New Object


HTTP/1.1 200 OK
Content-Type: application/json

{
  "status": "new",
  "diff": []
}

Response: No Changes


HTTP/1.1 200 OK
Content-Type: application/json

{
  "status": "unchanged",
  "diff": []
}

Status Values

StatusDescription
newObject with this ID does not exist on the server. Will be created on apply.
updatedObject exists and has differences. diff array contains the specific changes.
unchangedObject exists and is identical to the submitted definition.
errorComparison failed (e.g., permission denied, invalid type).

Diff Operation Types

OperationDescription
replaceA field value has changed. oldValue and newValue are provided.
addA new field or array element was added. newValue is provided.
removeA field or array element was removed. oldValue is provided.

POST /api/saved_objects/_bulk_apply

Apply multiple resource definitions in a single transactional operation. Creates objects that do not exist and updates those that do (upsert semantics).

Request


POST /api/saved_objects/_bulk_apply
Content-Type: application/json
osd-xsrf: true

{
  "resources": [
    {
      "type": "dashboard",
      "id": "cpu-monitoring",
      "attributes": {
        "title": "CPU Monitoring",
        "panelsJSON": [
          {
            "panelIndex": "1",
            "gridData": { "x": 0, "y": 0, "w": 24, "h": 12, "i": "1" },
            "type": "visualization",
            "id": "cpu-line-chart"
          }
        ]
      },
      "labels": {
        "env": "production",
        "team": "platform",
        "managed-by": "osdctl"
      },
      "annotations": {
        "owner": "platform-team@company.com",
        "last-applied-hash": "sha256:abc123..."
      }
    },
    {
      "type": "visualization",
      "id": "cpu-line-chart",
      "attributes": {
        "title": "CPU Usage Line Chart",
        "visState": "..."
      },
      "labels": {
        "managed-by": "osdctl"
      }
    }
  ],
  "options": {
    "dryRun": false,
    "overwrite": true,
    "createMissing": true
  }
}

Request Fields

FieldTypeRequiredDescription
resourcesarrayYesArray of resource definitions to apply
resources[].typestringYesSaved object type (e.g., dashboard, visualization)
resources[].idstringYesUnique resource identifier
resources[].attributesobjectYesResource attributes
resources[].labelsobjectNoKey-value labels for filtering
resources[].annotationsobjectNoFree-form metadata
options.dryRunbooleanNoIf true, validate and report what would change without persisting. Default: false.
options.overwritebooleanNoIf true, update existing objects. Default: true.
options.createMissingbooleanNoIf true, create objects that do not exist. Default: true.

Response: Success


HTTP/1.1 200 OK
Content-Type: application/json

{
  "success": true,
  "results": [
    {
      "type": "dashboard",
      "id": "cpu-monitoring",
      "status": "updated",
      "version": 6
    },
    {
      "type": "visualization",
      "id": "cpu-line-chart",
      "status": "created",
      "version": 1
    }
  ]
}

Response: Validation Failure

If any resource fails validation, the entire batch is rejected (transactional):


HTTP/1.1 400 Bad Request
Content-Type: application/json

{
  "success": false,
  "message": "Validation failed for 1 resource(s)",
  "results": [
    {
      "type": "dashboard",
      "id": "cpu-monitoring",
      "status": "valid"
    },
    {
      "type": "visualization",
      "id": "cpu-line-chart",
      "status": "error",
      "errors": [
        {
          "path": "attributes.visState",
          "message": "must be a valid JSON object"
        }
      ]
    }
  ]
}

Per-Resource Status Values

StatusDescription
createdObject was created (did not previously exist)
updatedObject was updated (existed with different content)
unchangedObject exists with identical content; no write performed
errorValidation or write failed for this resource

Dry-Run Example


curl -u admin:admin \
  -X POST "http://localhost:5601/api/saved_objects/_bulk_apply" \
  -H 'Content-Type: application/json' \
  -H 'osd-xsrf: true' \
  -d '{
    "resources": [
      {
        "type": "dashboard",
        "id": "test-dashboard",
        "attributes": { "title": "Test", "panelsJSON": [] }
      }
    ],
    "options": { "dryRun": true }
  }'

Optimistic Concurrency

When updating existing resources, you can include the If-Match header with the expected version number:


POST /api/saved_objects/_bulk_apply
If-Match: "5"
osd-xsrf: true

If the deployed version does not match, the server responds with 409 Conflict. This prevents overwriting concurrent changes from the UI or other tools. Omitting the header skips the version check (backward-compatible behavior).

POST /api/saved_objects/_export_clean

Export resources in a deterministic, Git-diff-friendly format. This is an alternative to the existing ndjson export that produces human-readable, sorted output suitable for version control.

Request


POST /api/saved_objects/_export_clean
Content-Type: application/json
Accept: application/yaml
osd-xsrf: true

{
  "type": "dashboard",
  "id": "cpu-monitoring"
}

Query Parameters

ParameterDefaultDescription
typeResource type to export
idSpecific resource ID (optional; omit to export all of a type)

Accept Header

ValueOutput Format
application/jsonDeterministic JSON (sorted keys, 2-space indent)
application/yamlYAML

Response (YAML)


HTTP/1.1 200 OK
Content-Type: application/yaml

apiVersion: dashboard/v1
metadata:
  name: cpu-monitoring
  labels:
    env: production
    managed-by: osdctl
    team: platform
  annotations:
    last-applied-hash: "sha256:abc123..."
    owner: platform-team@company.com
spec:
  title: "CPU Monitoring"
  description: "Production CPU metrics across all clusters"
  timeRange:
    from: "now-1h"
    to: "now"
  refreshInterval: "30s"
  panels:
    - name: cpu-usage
      type: visualization
      visualization: line
      gridPosition:
        x: 0
        y: 0
        w: 24
        h: 12
      query:
        language: PPL
        query: "source = metrics | where name = 'cpu.usage' | stats avg(value) by host"
      options:
        showLegend: true
  dataSources:
    - name: metrics-cluster
      type: opensearch
      default: true

Clean Format Design Principles

The clean export format differs from the existing ndjson export in several important ways:

Aspectndjson ExportClean Export
Key orderingArbitrarySorted (deterministic)
Server fieldsIncluded in bodySeparated into metadata block
Panel formatStringified JSON blob (panelsJSON)Structured array with named references
ReadabilityMachine-orientedHuman-readable
Diff qualityNoisy, hard to reviewClean, meaningful diffs

You can use these schemas for IDE autocompletion by referencing them in your JSON/YAML files or configuring VS Code's JSON Schema association.

Labels and Annotations

Labels and annotations are metadata attached to saved objects for organization, filtering, and tooling integration.

Labels

Labels are indexed and queryable key-value pairs. They are used for filtering, selection, and organizational grouping.

Constraints:

  • Keys and values are strings
  • Maximum 64 labels per object
  • Keys follow the pattern [a-zA-Z0-9._-/]+ (max 63 characters)
  • Values are free-form strings (max 256 characters)

Reserved labels:

LabelDescription
managed-byIdentifies the tool managing this object (e.g., osdctl). The UI shows a badge for managed objects.
envEnvironment label (e.g., production, staging, development)
teamTeam ownership label

Annotations

Annotations are stored but not indexed. They are free-form metadata for tooling and documentation.

Common annotations:

AnnotationDescription
ownerContact information for the dashboard owner
source-repoGit repository URL where the dashboard source lives
last-applied-hashSHA-256 hash of the last applied definition (used for drift detection)
osdctl.opensearch.org/sourceIndicates the source type (e.g., dashboards-as-code)

Querying by Labels

Extend the existing _find endpoint with label filters:


GET /api/saved_objects/_find?type=dashboard&labels=env:production,team:platform

This returns only dashboards that have both env=production and team=platform labels.

Managed-By Convention

When osdctl apply deploys a dashboard, it automatically sets:


{
  "labels": {
    "managed-by": "osdctl"
  },
  "annotations": {
    "last-applied-hash": "sha256:<hash-of-definition>"
  }
}

The OpenSearch Dashboards UI shows a visual indicator for objects with the managed-by label:

  • A badge reading "Managed by code" appears on the dashboard card and detail page.
  • A warning tooltip states "Edits may be overwritten by the next code deployment."
  • The UI does not block manual editing (users may need to make emergency changes).

The last-applied-hash annotation enables the CLI to detect drift: if the deployed hash differs from what osdctl last applied, someone made a manual change.

Error Responses

All endpoints use standard HTTP status codes and a consistent error format:

StatusDescription
200Success
400Invalid request (validation errors, malformed JSON)
401Authentication required
403Insufficient permissions
404Resource not found
409Conflict (version mismatch on optimistic concurrency check)
500Internal server error

Error response format:


{
  "statusCode": 400,
  "error": "Bad Request",
  "message": "Descriptive error message"
}
